# AIBCC Swift PoC — 합격 기준 (사전 고정)

- 근거: 사용자 우선순위(2026-10-31) P0 터미널 품질 · P1 산출물 .md 뷰어, Council `20261031_153914_85165`(합의도 87) 결정문.
- 이 문서는 **구현 첫 커밋 이전에** 고정한다. 이후 변경은 별도 커밋과 사유를 남긴다.
- 결과는 항목별 `pass` / `fail` / `unverified` 3상태. 원인은 `app` / `wrapper` / `engine` / `tui` / `unknown` 5분류. **원인 미상(unknown) P0 결함은 fail**.
- 증거: PTY 수신 hex, PTY winsize(`stty -f <tty> size`), 앱 grid(`TerminalViewState.surfaceSize`), 스크린샷.
- IME 결과는 층별로 따로 집계하고 합산하지 않는다: `imeCallbackContract`(NSTextInputClient 직접 호출) · `syntheticEventPath`(in-process 합성 NSEvent) · `physicalKeyboardIME`(사람). 합성 이벤트가 IMK를 경유했는지 확인되지 않으면 그 층은 `unverified`. 단, 중복 송신·오배달처럼 독립 확인된 실패는 `fail`.
- 레퍼런스: 같은 초기 크기·같은 시퀀스로 PoC, aibcc v1.6.1, Terminal.app, iTerm.app 비교. 레퍼런스와 같다는 사실이 엔진 무결함을 증명하지는 않는다.

## 차단 표기

`B` = Go 차단(blocking), `N` = 비차단(기록만), `O` = 선택 항목.

## 5. 안정성·성능 (P0)

부하 조건은 **측정 전 고정**: 출력 = 10만 줄(행당 ASCII 80자 + 한글 10자), scrollback 기본값, 분할 1/4, 측정 구간 = 출력 시작~종료. 입력이 PTY에 도달하는 시간과 화면 반영 시간을 따로 잰다.

| ID | 항목 | 차단 | 측정 |
|---|---|---|---|
| ST-01 | 4분할에서 IN·RS·SC 핵심 항목 동일 | B | 위 항목 재실행 |
| ST-02 | 대량 출력 중 입력 → PTY 도달 p95 ≤ 사전 등록 후보값 max(50ms, v1.6.1 값) | B | 시간 |
| ST-03 | 대량 출력 중 최장 정지 ≤ v1.6.1 값 | N | 시간 |
| ST-04 | 셸 종료 시 pane 정리, 앱 종료 시 자식 프로세스 정리(좀비·고아 0) | B | `ps` |
| ST-05 | OSC 9/777 알림·bell이 앱 이벤트로 수신(Attention 연계) | N | 이벤트 로그 |

## 8. 빌드 (관문 0)

CLT `swift build` → `.app` 패키징(프레임워크 먼저 서명 후 앱 서명, `--deep` 금지, 샌드박스 off, TCC 보호 폴더 밖) → 실행. 항상 `.app`으로 실행. 버전·Ghostty 출처 커밋·디스크 사용량 기록, 여유 3GB 미만이면 중단.

## 9. 판정

- **엔진 후보 통과**: 1~6의 `B` 항목 전부 pass(사람 검사 `physicalKeyboardIME` 포함).
- **제품 전환 Go**: 엔진 후보 통과 + 7의 `B` 전부 pass + v1.6.1 대비 회귀 0 + 세션·scrollback 경로 확보 + Xcode 없이 재현 가능한 빌드.
- 사람 검사만 남으면 최종 판정만 보류하고 나머지는 진행. Claude는 사람 검사 통과를 대신 선언하지 않는다.
- No-go → Tauri 유지 + 같은 디자인 명세, 렌더러 번들 이관.
